# client 功能说明

new-api 网关管理面的轻量 HTTP 客户端（internal/newapi 根包：client.go / routes.go / page.go / consts.go / mask.go），全部域子包与工具层共用的传输底座。

## 职责

- **传输**（client.go）：`Client`（BaseURL + Token + http.Client 超时）；`Do`（标准信封请求，data 原样返回）、`DoTopLevel`（整包顶层 JSON 解析，用于 time/error_code 放顶层的端点如渠道测试）、`GetJSON`（GET + data 解到 out）
- **鉴权**：面板 PAT，`Authorization: Bearer <pat>`；Token 为空则不带该头（公开端点可用）。官方已移除 New-Api-User 头要求
- **错误分类**（APIError）：`{StatusCode, Message, Reachable}`——网络层失败 Reachable=false（网关不可达）；网关应答但 HTTP≥400 或 success:false 则 Reachable=true。「网关挂了」和「查询/业务错」由此区分
- **端点常量**（routes.go）：上游全部路径的唯一耦合点，按 公开/ops/admin 分组注释
- **共享件**：`Paged[T]`/`PageResult[T]` 分页壳 + `Itoa`/`Itoa64` 查询参数工具；`QuotaPerUnit=500000.0`（quota→美元）；`MaskKey`（头尾各 4 位掩码，幂等）

## 边界

- 零业务逻辑：不解释任何域语义，只收发/解包/分类错误
- 不做重试、不做连接池调优（net/http 默认）；响应体上限 8MB（LimitReader）
- `Do` 把 success:false 当错误返回；`DoTopLevel` 相反——业务失败不报错（交调用方按语义处理），只有网络不可达/非 JSON 应答才报错。选错入口是最常见误用
- 掩码只在「出」方向：MaskKey 幂等（已含 `***` 原样返回），过短（≤10 字符）取头尾各 2 位
