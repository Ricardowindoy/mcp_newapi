## doRequest 细节

- URL：`BaseURL + path`（NewClient 已 TrimRight 尾斜杠），query 非空才拼
- Header：`Accept: application/json`；body 非空加 `Content-Type: application/json`；`Token != ""` 才加 `Authorization: Bearer`
- body 任一类型 JSON 编码（域函数直接传 map 或 struct）
- 响应：`io.LimitReader(resp.Body, 8<<20)`；解 envelope 失败 → APIError{Reachable:true, 截断 200 字符原文}（典型场景：反代错误页 / 路径不存在）
- 网络层 `c.http.Do` 出错 → APIError{Reachable:false}（上游超时也是这条路径，http.Client.Timeout 触发时 err 非 nil）

## Do vs DoTopLevel 语义（关键契约）

| | Do | DoTopLevel |
|---|---|---|
| 正常返回 | env.Data（RawMessage） | 整个顶层 JSON 解成 map[string]any |
| success:false | **返回错误**（Reachable=true） | 不报错，map 里带 success=false |
| 网络不可达 | APIError Reachable=false | 同左 |
| 非 JSON | APIError（截断原文） | APIError「非 JSON 应答」 |

上游契约依据：渠道测试 `GET /api/channel/test/:id` 把 `time`/`error_code` 放顶层而非 data，所以只有 DoTopLevel 能拿到；这也是 `channels.Test` 用它的原因。

## APIError.Error() 文案

- Reachable=false → `newapi 网关不可达: <msg>`
- StatusCode>0 → `newapi 应答 <code>: <msg>`
- 其余 → `newapi 业务错误: <msg>`

handler.ErrResult 依赖该类型做 `errors.As` 分支，改字段名/语义必须同步 handler 与测试。

## routes.go 常量分组

- 公开：RouteStatus / RouteModels / RoutePricing / RouteData（dashboard 聚合）
- 读：RouteChannels / RouteChannelDetail(%d) / RouteTokens / RouteLogs / RouteLogStat / RouteOptions（GET 系统设置列表，上游已脱敏）
- ops：RouteChannelTestAll / RouteChannelTest(%d) / RouteChannelBalAll / RouteChannelBal(%d) / RouteChannelStatus(%d)（body {status:1|2}）/ RouteTokenSearch / RouteTokenID(%d)
- admin：复用 RouteChannels——POST 创建、PUT 更新（PATCH 语义，含 tag 字段）；DELETE 用 RouteChannelDetail；RouteChannelTag（PUT 按 tag 批量编辑）/ RouteChannelTagEnable、RouteChannelTagDisable（POST 按 tag 批量启停）；复用 RouteOptions——PUT 更新 {key,value}
- 例外：RelayProbe（domains/status）裸写 `/v1/models`（relay 面不在管理面路由组，未提常量）

## 修改注意

- 改鉴权方式：只动 doRequest 的 header 段
- 上游加端点：只加 routes.go 常量 + 对应域函数，client.go 不动
- 响应体上限、超时默认（10s）如需调整，注意 NewClient 的 timeout≤0 兜底与 config 的 Validate 各有一份 10s
