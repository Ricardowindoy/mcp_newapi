# handler 实现详细说明

## 文件清单

| 文件 | 内容 |
|---|---|
| helpers.go | Handler 签名 / JSONResult / ErrResult / orDefault |
| read.go | read 档 13 个 handler + autoban 纯函数（isAutobanOptionKey / allChannels / errStats / classifyBanCause） |
| ops.go | ops 档 6 个 handler |
| admin.go | admin 档 6 个 handler + orDefaultStr / keysOf |
| report.go | jiyuan_report handler（read 档，调 reporter） |
| read_test.go | autoban 纯函数单测（键筛选 / errStats 聚合 / 原因分类） |

handler 工厂统一形态：`func StatusHandler(client *newapi.Client, rep *reporter.Store) Handler` —— 装配时闭包注入 client 与报表从库连接（registry 模块调用）；除 jiyuan_report 外均不使用 rep。

## helpers.go

- `JSONResult`：MarshalIndent（两空格缩进）；编码失败返回工具错误「结果编码失败」
- `ErrResult`：`errors.As` 提 APIError → `[reachable=%v status=%d] %s`；其余 err 原文。注意返回值恒为 `(result, nil)`——错误信息在工具结果里，不让 Go error 冒泡
- `orDefault(req, key, def)`：`req.GetInt(key,def)` 结果 >0 才用，否则 def——**调用方传 0 等于没传**

## read.go 要点

- `StatusHandler`：`status.Get` 后再发 relay 探测（`context.WithTimeout(ctx, 5s)` 独立超时，defer cancel）；探测失败不致命，输出 `relay_reachable:false + relay_error`。uptime 由 `now - StartTime` 现算
- `ModelsHandler`：汇总 group_count / model_count（各组长度和）
- `LogsHandler`：Query 组装——page/page_size/type 走 orDefault（0=全部时不发 type）；start/end_timestamp 仅 >0 收；model_name/token_name 空串不收；channel 仅 >0 收
- `UsageSummaryHandler`：days 夹取（≤0 或 >365 回落 7）；start=now-days*86400；聚合结果附 `total{calls,tokens,quota,quota_usd}`（quota_usd=totalQuota/QuotaPerUnit）
- `PricingHandler`：域函数返回 RawMessage，直接 `JSONResult(json.RawMessage(raw))` 二次透传（不重排字段）
- `ListOptionsHandler`：`options.List`（域内按 key 排序）→ 输出 `count + options[{key,value}]`；无参数
- `SuccessRateHandler`：窗口（hours 默认 24 夹取 1-720；start/end_timestamp 都 >0 才覆盖）；`logs.Count` 对 type=2/5 各查一次（page_size=1 只取 total）；total=0 输出 success_rate:null+「无匹配日志」，否则 success_rate（4 位小数）+ success_rate_pct；输出附 filters 回显与重试近似性 note
- `AutobanConfigHandler`：`options.List` 后按 `isAutobanOptionKey` 筛选（lowercase 含 automatic / ==channeldisablethreshold / ==retrytimes / 前缀 monitor_setting. / channel_affinity_setting.），global_switch_enabled 从 AutomaticDisableChannelEnabled=="true"（EqualFold+TrimSpace）推导；`allChannels`（pageSize=100 循环拉全量）普查 auto_ban 三态——Summary.AutoBan 为 *int，**nil=上游 NULL（视为关）与显式 0 必须可区分**，not_enabled 清单带 reason；输出附写入口 note（update_option/autoban_codes/update_channel）
- `AutobanAnalysisHandler`：channel>0 → `channels.Get` 单渠道；否则 `allChannels` 过滤 status==3 或 StatusReason!=""（覆盖手动恢复后 reason 残留的渠道）；空目标输出 targets_analyzed:0+引导；每目标 `logs.Count`(type=5+channel+窗口) 精确总量、total>0 再 `logs.Search`(Page=1,PageSize=sample) 采样——Count/Search 失败不中断整体（该渠道 view 附 error 字段继续）；`errStats`（按 content 聚合 top5 含 last_seen、按模型 top5、last_error_at）+ `classifyBanCause`（关键词首中：quota_exhausted→model_issue→timeout→upstream_unreachable→other，大小写不敏感；total==0 → no_error_logs）；输出附 window/targets_analyzed/启发式 note
- `JiyuanReportHandler`（report.go）：rep==nil → 「报表功能未配置：需要在生产配置 [report] 段设置 db_dsn_file（或 db_dsn / 环境变量 NEWAPI_REPORT_DB_DSN）后重启 MCP」；name_like 空串回落「基元」、days 夹取 1-30（缺省 4）→ `rep.JiyuanReport` → 结构化报表 JSON（channels/models/details/daily/total/missing_prices）

## ops.go 要点

- `TestChannelHandler` / `UpdateBalanceHandler` / `SetChannelStatusHandler`：id≤0 → 参数错误；UpdateBalance 刷新后 `channels.Get` 回查，回查失败不影响成功结果（降级输出 refreshed:true）
- `CreateTokenHandler`：name TrimSpace 非空、≤50；`ModelLimitsEnabled` 按 model_limits 非空推导；`!UnlimitedQuota && RemainQuota<=0 → UnlimitedQuota=true`（0 额度令牌不可用）；输出 key_masked + note，非 unlimited 才附 remain_quota(_usd)
- `DeleteTokenHandler`：confirm≠true → 「删除不可恢复：请确认后显式传 confirm=true」

## admin.go 要点

- `CreateChannelHandler`：type>0、key、models 三必填；group 缺省 default（orDefaultStr）；输出 created+id+model_mapping+hint（key 不回显，建议 test_channel 验证）
- `UpdateChannelHandler`：字符串字段白名单 name/key/models/base_url/group/model_mapping/test_model/type（非空才收）；数值 priority/weight（≠0 才收）；**auto_ban/tag 三态**：按 `req.GetArguments()` 是否含该键判断「传没传」——auto_ban 出现即写上游 1/0（上游 `AutoBan *int`，nil 视为 false），tag 出现即写（空串=清除，上游 PatchChannel 内嵌 model.Channel.Tag）；**白名单不含 status**（启停走 ops 工具，上游也拒绝 PUT 带 status）；fields 为空 → 「未提供任何要更新的字段」；成功后回查详情，回显 name/models/priority/group/**model_mapping**（显式输出，改后空串=已清空），回查失败降级输出 fields 清单
- `DeleteChannelHandler`：confirm 同 delete_token
- `UpdateOptionHandler`：key TrimSpace 非空（提示先 list_options 查键名）、value 非空（布尔/数字都以字符串形态传）、confirm≠true → 「系统设置全局生效：请确认后显式传 confirm=true」；成功输出 updated+key+value+hint（部分设置需重启/等下一轮任务生效）
- `AutobanCodesHandler`：action=list 直接 `options.StatusCodesList`；add/remove/set 需 confirm=true 且 codes 非空（逗号分隔直接 split 交域层解析，非法 token 域层 fail-fast）；action/target 先白名单校验再收 confirm
- `TagChannelsHandler`：action=edit|enable|disable + tag 必填 + confirm 必填；enable/disable → `channels.SetTagStatus`；edit 从 GetArguments 判存在收集 new_tag（TrimSpace 非空，清空引导用 update_channel tag=""）/priority/weight（≥0）/models/model_mapping/group → `channels.EditByTag`，0 字段报错；上游 data 原样透传
- `keysOf`：map 键列表（输出 fields 命中情况）

## 修改注意

- 新增工具 handler：在对应档位文件加工厂函数 → registry 模块加表项（两处缺一不可，registry_test 会校验一致性）
- 输出 map 键名是对 Agent 的接口契约，改名视为破坏性变更，需同步 .docs 与测试
- 错误文案面向 Agent（含重试指引，如 confirm 提示），勿改成纯英文/丢上下文
