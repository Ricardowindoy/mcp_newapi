# domains 功能说明

new-api 业务域子包集合（internal/newapi/{status,models,channels,tokens,logs,options}），架构上「一域一包」：上游端点 → 域函数，上游响应 → 裁剪 DTO。handler 层只调域函数，不见上游细节。

## 各域职责

- **status**：`Get` 站点公开状态（/api/status，无需 PAT，裁剪 version/start_time/register_enabled 等关键字段）；`RelayProbe` 用 /v1/models 探测中继活性——返回 401/403 也算活着（APIError.Reachable=true 即可达）
- **models**：`List` 全站模型（data 为 分组→模型数组，透传并组内排序）；`Pricing` 模型倍率（原始 data 透传，实例可能禁用该端点）
- **channels**（一域三文件）：
  - channel.go 读：`List`（分页+status 过滤，0=全部时不带参数）、`Get` 单渠道详情；Summary 含 status_reason（从 other_info JSON 里抠出）、model_mapping（上游 JSON 字符串原样，无映射不出字段）、auto_ban（*int：nil=上游 NULL 未设置（GetAutoBan 视为关）/0=关/1=开）与掩码 key
  - ops.go 运维：`Test` 单渠道测试（**业务失败是有效结果**，走 DoTopLevel）、`TestAll` 触发全量测试（异步任务，返回 task 信息）、`UpdateBalance` 刷新余额（部分渠道类型不支持）、`SetStatus` 启停（body {status:1|2}，返回 changed bool）
  - admin.go 管理：`Create`（body {mode:"single",channel:{...}}；上游不回 id，按名 List 回查）、`UpdateFields`（PATCH 语义，只发要改字段+id）、`Delete`、`EditByTag`（PUT /api/channel/tag 按 tag 批量编辑）、`SetTagStatus`（POST /api/channel/tag/enabled|disabled 按 tag 批量启停）
- **tokens**（读写一体，普通 PAT）：`List` / `Create`（POST 后按 keyword 搜回 id+掩码 key）/ `Delete`；Status 语义 1=启用 2=禁用 3=过期 4=耗尽
- **logs**：`Search` 日志检索（Query 零值字段不发送）、`Count` 按条件计数（只取分页 total，成功率查询的底座）、`StatWindow` 时间窗总量（quota/rpm/tpm）、`AggregateByModel` 走 /api/data/ 按模型聚合（quota_usd 换算 + 按消费额降序）
- **options**（系统设置，受限封装）：`List` 全量键值对（GET /api/option/，**上游已过滤敏感键** *Token/*Secret/*Key 等后缀与 theme.frontend，附合成键 CompletionRatioMeta；域内按 key 排序）；`Update` 写单键（PUT body {key,value}，value 字符串形态，上游统一转 string）——**上游不校验 key 白名单**，调用方必须先 List 确认键名；`StatusCodesList/Modify` autoban 状态码增删查改（本地镜像上游区间代数：解析排序合并相邻/重叠，add 查重、remove 拆区间，产出上游可直接解析的规范串）

## 边界

- 只依赖 client 模块（共享件 + Do/DoTopLevel/GetJSON），不依赖工具层
- 掩码边界：raw→toSummary 构造时过 MaskKey，**完整 key 永不出域包**
- 每包顶部注释写明上游契约（controller 文件名、请求/响应形态、坑），上游漂移时按注释定位核对
- 上游已知坑（详见 _mustread/开发规范.md）：PUT 渠道是 PATCH 语义但 status 字段被拒；created_time/test_time/response_time/balance 只读字段传入会被清零；创建渠道/令牌不回 id 需按名回查
