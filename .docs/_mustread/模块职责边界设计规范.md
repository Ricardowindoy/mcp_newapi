# 模块职责边界设计规范

本文件是必读文档，修改需用户显式同意。

## 分层与单向依赖

```
entry (cmd/newapi-mcp)
  └─→ registry (internal/mcp: registry.go + server.go)
        └─→ handler (internal/mcp/handler)   ←—— 工具层·薄壳
              ├─→ domains (internal/newapi/{status,models,channels,tokens,logs,options})
              │     └─→ client (internal/newapi 根包)   ←—— 传输层
              └─→ reporter (internal/reporter)   ←—— 报表域·叶子包（直连报表从库）
config (internal/config) ——独立横向模块，只被 entry 使用
```

依赖只能自上而下（entry → registry → handler → domains → client；handler 另可引用叶子包 reporter），**禁止反向引用、禁止跨层引用**。handler 引用 `internal/newapi` 根包仅限共享件（`Client`/`APIError`/`QuotaPerUnit`）。config 不感知 HTTP/MCP，仍只被 entry 使用——报表从库连接由 entry 从 config 的 ReportDSN() 构造 `reporter.Store` 后经 `mcp.NewServer(client, writemode, rep)` 注入，registry/handler 不 import config（rep=nil=报表未配置，工具仍注册、调用时报配置不足）。

## 各层职责与禁令

| 层 | 只做 | 禁止 |
|---|---|---|
| entry | flag 解析、装配（含 reporter.Store 注入）、stdio 启动 | 任何业务逻辑、任何 stdout 输出（JSON-RPC 专线） |
| registry | 工具声明表 + 档位过滤 + 装配 | 参数解析、业务逻辑 |
| handler | 解析参数 → 调域函数 → 统一输出 | 业务逻辑下沉；直接拼上游请求 |
| domains | DTO 裁剪 + 域函数 + 上游契约注释 | 依赖工具层；泄露完整 key |
| reporter | 直连报表从库聚合 + 结构化结果返回 | 持有凭据；感知 HTTP/MCP；exec 外部脚本 |
| client | HTTP 传输/鉴权/信封解包/错误分类/共享常量 | 业务语义 |
| config | 配置装载/校验 | 感知 HTTP/MCP |

## 核心约定（改代码前必读）

1. **registry.go 唯一汇总表**：新增/调整对外工具只改表项（Name/Tier/Options/Handler 工厂）+ 对应 handler 文件，`server.go` 不动。handler 实现按档位放 `read.go` / `ops.go` / `admin.go` / `report.go`。外部依赖型工具（如 jiyuan_report）同样表内注册：`rep` 为 nil 时工具仍注册、调用时报「报表功能未配置」，**不做表外条件注册**。
2. **能力分档靠不注册**：低档 writemode 下高档工具根本不注册（而非注册后拒绝），减少 Agent 误选。tier 数值比较：read=0 < ops=1 < admin=2。
3. **routes.go 唯一耦合点**：上游端点路径漂移只改这里；域包只引用常量，不写裸路径（RelayProbe 的 `/v1/models` 是历史例外）。
4. **一域一包**：域子包 = raw DTO（上游原字段）+ Summary（裁剪 DTO）+ `toSummary()` 构造时掩码 + 域函数 + 顶部上游契约注释。掩码后完整 key 永不出域包。reporter 是「外部数据源域」特例：无 raw/Summary 与 HTTP 端点，直连报表从库（SQL 聚合 + BuildReport 纯函数），凭据经 entry 注入、本包不读配置。
5. **薄壳约定**：handler 不做业务判断；输入校验（必填、id>0、confirm=true）除外。
6. **错误分类**：`newapi.APIError{Reachable, StatusCode, Message}`——网络层失败 Reachable=false（「网关不可达」）；网关应答但业务失败 Reachable=true。**业务性失败（如渠道测试不通）是有效结果而非错误**：这类顶层字段端点走 `DoTopLevel`，success:false 交调用方按业务语义处理。
7. **分页**：上游列表参数是 `p`（1 起）+ `page_size`；统一分页壳 `{page,page_size,total,items}`，用 `Paged[T]`（原始）→ `PageResult[T]`（对外）。
8. **配置不足显式报告**：可选能力（如报表）未配置时工具保持注册，调用时返回明确错误给调用方；不做静默降级、不做条件注册。

## 新增业务域的标准流程

1. `internal/newapi/<域>/` 新建域子包（raw + Summary + toSummary + 域函数 + 契约注释）；**外部数据源型域**（如 reporter）则建 `internal/<域>/` 叶子包 + 独立 `.docs/<域>/`
2. `routes.go` 加端点常量（reporter 类无 HTTP 端点则跳过）
3. `registry.go` 加表项（选对 Tier）
4. `handler/<档位>.go` 实现 Handler 工厂（外部数据源型放 `report.go`，经注入的 Store 调用）
5. `.docs/domains/`、`.docs/handler/`、`.docs/registry/`、`.docs/client/` 文档同步
6. 纯逻辑单测（httptest）覆盖新契约
