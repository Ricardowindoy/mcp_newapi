# 开发规范

本文件是必读文档，修改需用户显式同意。

## 构建与测试（推送前硬性要求）

任何 `git push` 之前，必须在本机跑通以下全部检查，**全部通过才允许推送**：

```sh
export PATH=/opt/go/bin:$PATH   # go1.26.6 linux/arm64（勿用旧路径 ~/tools/go/bin）
go vet ./... && go build ./...
go test ./...                   # 纯逻辑单测（httptest，不碰真实网关）
```

1. Go 缓存三件套默认 `~/go` 只读会以诡异方式失败，必须显式设置：`GOCACHE=/home/radxa/.cache/go-build GOMODCACHE=/home/radxa/.cache/go-mod GOPATH=/home/radxa/.cache/go-path`（仓库内 `.gocache/.gomodcache/.gopath/` 是历史工作区重定向，已 gitignore，勿入库）。
2. 修复 bug 后必须补对应测试用例，禁止只改代码不加测试。测试约定：纯逻辑用 httptest（见 `client_test.go`、`channels/ops_test.go`），不依赖真实网关。
3. 推送历史干净：合并小提交，message 说明动机与验证结果（沿用 `M1:/M2:...` 里程碑风格）。

## 安全规范（硬性红线）

1. **PAT / key / 完整 sk- 永不入库**：生产配置在 `~/.dsh/newapi-mcp.toml`（0600），PAT 经 `token_file` 间接引用 `~/.dsh/newapi.pat`；仓库内只有 `newapi-mcp.example.toml` 示例（占位值）。
2. **任何 MCP 响应不透出完整 key**：域包 raw→Summary 构造时必须过 `newapi.MaskKey`；新增返回密钥的字段前先想掩码。
3. **删除类工具必须显式 `confirm=true`** 才执行（delete_token / delete_channel）；**update_option 同样强制 confirm=true**（系统设置全局生效）。
4. `redemption/`（兑换码）不封装——纯风险无收益。`option/`（系统设置）**受限封装**（2026-08-30 用户批准）：仅 `newapi_list_options`（read 档读，上游已过滤敏感键）与 `newapi_update_option`（admin 档写，confirm 门禁），描述文案必须标注「危险操作：全局生效、key 不做白名单校验」；其余全局运营面仍不封装。

## 上游兼容维护

- new-api 迭代快，**端点路径只改 `internal/newapi/routes.go`**（唯一耦合点）；响应字段变化只改对应域包 DTO。
- 实现前以目标版本上游 router/controller 为准逐个核对；参考源码快照放 `.upstream/`（gitignore）。
- 已知上游坑（勿重复踩）：渠道更新 PUT 是 PATCH 语义但 status 被拒（启停走 `POST /api/channel/:id/status`）；`created_time/test_time/response_time/balance` 只读字段传入会被清零；创建渠道/令牌不回传 id，需按名回查；`pricing` 端点可能被实例禁用。

## 文档同步

1. 修改某模块代码后，同一回合更新该模块 `.docs/<模块>/` 文档（功能说明/实现详细说明），避免漂移。
2. 必读文档（`_mustread/**`、vault README）修改必须走 doc_propose 提案，用户 approve 后生效。
3. 新增业务域 = 新域子包 + routes.go 常量 + registry.go 表项 + handler 实现 + `.docs` 文档同步。

## DSH 挂载

生产经 `~/.dsh/mcp-newapi-wrapper.sh`（exec `bin/newapi-mcp --config ~/.dsh/newapi-mcp.toml`）挂进 cordis.patch.yml；改 wrapper/二进制后需重启 DSH 生效。stdio 传输下 **stdout 只跑 JSON-RPC，日志一律 stderr**。
