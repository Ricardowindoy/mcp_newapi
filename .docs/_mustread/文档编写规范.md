# 文档编写规范

本文件是必读文档，修改需用户显式同意。

## 文档体系（三层，受众不同）

| 层 | 位置 | 受众 | 内容 |
|---|---|---|---|
| 使用者文档 | `docs/{guide,design,project}/` | 想把项目用起来的人 | 快速上手 / 配置 / 工具参考 / 客户端接入 / 上游坑 / 治理 |
| 维护者 vault | `.docs/`（本目录） | 改代码的人和 AI | 模块四件套 + `_mustread/` 必读规范 |
| 根目录 | 仅 `README.md` + `README.en.md` | 第一眼访客 | 概览 + 全部文档的导航 |

**其他文档一律不放根目录**（用户约定，2026-08-30）。`newapi-mcp.example.toml`（配置模板）与 `examples/`（接入示例）不是文档，分别留在根目录与 examples/。

## 双语规范

- 中文为主 `<name>.md`，英译伴生 `<name>.en.md`；**改动中文篇必须同回合同步英译**（标题/表格行/列表/代码围栏数与中文篇一致）
- 语言切换行：中文篇顶部 `> [English](<name>.en.md) | 中文`；英译篇顶部 `> [中文](<name>.md) | English`
- 不翻译：工具名（`newapi_*`）、参数名、配置键、档位值（read/ops/admin）、路径、URL、代码块内容（仅译注释）；中文示例数据（渠道名等）可保留原文

## 链接与目录结构

- 一律相对链接；**移动/重命名文档后必须全仓链接校验再提交**：
  ```sh
  git ls-files '*.md' | grep -v .doc-vault | while read -r f; do d=$(dirname "$f"); \
    grep -oE '\]\(([^)#]+)\)' "$f" | sed -E 's/\]\(//; s/\)//' | while read -r l; do \
    case "$l" in http*|\#*) ;; *) [ -e "$d/$l" ] || echo "MISSING in $f: $l";; esac; done; done | sort -u
  ```
- 中文篇与其英译的互链各指向对应语言版本；指向无英文版文件的链接保持原路径
- 目录按受众分（docs/ 下 guide/design/project），不新增扁平堆积；单目录 md 超过 ~8 个就该拆子目录
- 教训：批量改链接时 sed 的捕获组写法容易只匹配 `.en.md` 变体而漏中文 `.md`，改完必须跑上面校验

## vault 模块文档（.docs/）

- 每模块四件：`module.json`（name/summary/paths/uses）+ `README.md`（≤0.5KB）+ `功能说明.md`（≤8KB）+ `实现详细说明.md`（≤16KB），超出拆章节
- **module.json 的 summary 是 doc_find 的数据源，是最高频漂移点**——改模块代码后除正文外必须核对 summary 与 paths
- 功能说明 = 职责与边界（读代码前看）；实现详细说明 = 文件映射/数据流/坑（改代码前看，含 uses 声明的底层模块）
- 已知漂移高发清单：工具数量计数（17→22→23）、里程碑完成状态、能力口径中间态（如「本地脚本回读」vs「直连从库」）——提交前 grep 旧值

## 书写风格

- 每篇开头一句话定位：本文档是什么、给谁看
- 参数/字段用表格（参数 | 类型 | 必填 | 说明）；步骤用有序列表；对比用表格不用长段文字
- 示例 JSON 必须用真实 DTO 字段名（从代码 grep `json:"` 取），不编造字段
- 示例数据一律占位：`https://your-newapi.example`、`sk-a***7890` 形式掩码；**任何真实 key/PAT/DSN/内网密码不入任何文档**

## 变更流程

- `_mustread/**` 与本 README：doc_propose 提案 → 用户 approve 生效；用户在聊天中明确批准后，可 write 临时文件 + shell cp 落盘（护栏只拦 write/edit 工具，不拦 bash）
- `docs/` 与根 README：普通文档直接改，同回合同步英译、`docs/README.md` 索引与根 README 导航表
- 文档重构（移动/改名/拆目录）后：链接校验 → 同回合提交推送，不积压
