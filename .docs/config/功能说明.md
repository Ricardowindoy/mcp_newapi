# config 功能说明

独立横向配置模块（internal/config/config.go，约 113 行）：把「内置默认值 → TOML 配置文件 → 环境变量」三层来源装配成一份最终 `Config`，供 entry 装配 client 与 server 用。

## 职责

- 定义配置结构：`Config.NewAPI`（`NewAPIConfig`）五字段——`base_url` / `token` / `token_file` / `writemode` / `timeout_seconds`（TOML tag 对应）
- `Load(path)` 一站式装载：默认值 → TOML 解码（path 为空则跳过，缺文件也 OK）→ 环境变量覆盖 → token_file 解析 → 校验
- 环境变量覆盖（非空才覆盖）：`NEWAPI_BASE_URL`（去尾斜杠）/ `NEWAPI_TOKEN` / `NEWAPI_WRITEMODE` / `NEWAPI_TIMEOUT`（秒，非法值静默忽略）
- `resolveTokenFile`：token 为空且配置了 token_file 时读文件首行作 PAT（密钥不写进配置文件本体）
- `Validate`：base_url 必填；writemode 只接受 `read` / `ops` / `admin`（三档常量 `ModeRead/ModeOps/ModeAdmin`）；timeout ≤0 时回落 10s
- 自带单测（config_test.go，5 用例），示例配置 `newapi-mcp.example.toml`

## 边界

- 不感知 HTTP / MCP：只产出纯数据配置，如何使用由调用方决定
- 不做默认值兜底之外的「智能」处理：writemode 非法直接报错（fail-fast），不静默降级
- 生产配置在 `~/.dsh/newapi-mcp.toml`（0600）+ `token_file` 指向 `~/.dsh/newapi.pat`；仓库内只有占位示例，PAT 永不入库
