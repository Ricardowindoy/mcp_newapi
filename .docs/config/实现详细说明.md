## 装配顺序（Load）

```
Defaults()                          # WriteMode=read, TimeoutSec=10, BaseURL=""
 └→ toml.DecodeFile(path, cfg)      # path=="" 跳过；文件不存在不算错，解析错误才报
 └→ applyEnv()                      # NEWAPI_* 环境变量，非空才覆盖
 └→ resolveTokenFile()              # Token=="" 且 TokenFile!="" 才读文件首行
 └→ Validate()                      # base_url 必填 / writemode 白名单 / timeout≤0→10
```

关键语义：

- **优先级**：环境变量 > TOML > 默认值。env 覆盖是「非空才覆盖」，所以 TOML 里的空串不会清掉 env。
- **token 三来源**：env `NEWAPI_TOKEN` > TOML `token` > token_file 首行。显式 token 存在时 token_file 不读。
- **token_file 解析**：`SplitN(s, "\n", 2)[0]` + TrimSpace；读失败 / 首行为空都报错（含路径）。
- **BASE_URL 规范化**：env 来源 `TrimRight(v, "/")`；TOML 来源不在本模块去尾斜杠（client.NewClient 会再 TrimRight，双保险）。
- **NEWAPI_TIMEOUT**：Atoi 失败或 ≤0 时静默保持原值（不报错）——容错语义，与 writemode 的 fail-fast 不同。

## 类型与字段

```go
type NewAPIConfig struct {
    BaseURL    string `toml:"base_url"`
    Token      string `toml:"token"`
    TokenFile  string `toml:"token_file"`
    WriteMode  string `toml:"writemode"`
    TimeoutSec int    `toml:"timeout_seconds"`
}
```

注意命名不一致点：TOML 键是 `timeout_seconds`，环境变量是 `NEWAPI_TIMEOUT`（历史约定，勿改其一漏其二）。

## Report 段（报表从库，0.5.0 起）

```go
type ReportConfig struct {
    DBDSN     string `toml:"db_dsn"`      // 直连 DSN（不推荐，密钥落配置本体）
    DBDSNFile string `toml:"db_dsn_file"` // DSN 文件路径（读首行，0600；推荐，同 token_file 模式）
}
func (c *Config) ReportDSN() string  // env NEWAPI_REPORT_DB_DSN > db_dsn > db_dsn_file 首行；空串=未配置
```

- **允许密钥缺席**：Report 段整体可缺省——ReportDSN() 返回空串时 entry 传 nil Store，jiyuan_report 工具仍注册、调用时报「报表功能未配置」错误（配置不足必须显式报告调用方，不做静默降级/条件注册）。
- ReportDSN 读文件失败/首行为空都**静默返回空串**（与 resolveTokenFile 的 fail-fast 不同：报表是可选能力，不阻断 MCP 启动）。
- DSN 形态：`user:pass@tcp(host:port)/db?charset=utf8mb4`（go-sql-driver/mysql）。

## 修改注意

- 新增配置项：加字段（带 toml tag）→ Defaults 给默认 → applyEnv 加 env 覆盖（如需）→ Validate 加校验（如需）→ 补测试 → 示例 toml 同步。
- 本模块无任何依赖（仅标准库 + BurntSushi/toml），保持零内部依赖。
