# reporter 实现详细说明

## 文件清单

| 文件 | 内容 |
|---|---|
| reporter.go | Store/Open/JiyuanReport（三条 SQL）/BuildReport（纯聚合）；DTO: Price/Agg/ChannelAgg/ModelAgg/DetailAgg/DailyRow/Report |
| reporter_test.go | TestBuildReportCostAndAggregation（消费公式/聚合/排序/缺价/负数钳制） |

依赖：`github.com/go-sql-driver/mysql`（驱动注册）+ database/sql。**无 HTTP、无 config 依赖**（DSN 由 entry 经参数注入）。

## 数据流

```
entry: rep = reporter.Open(cfg.ReportDSN())   # DSN 空 → nil Store
registry: def.Handler(client, rep)            # 工厂统一带 rep
handler: rep==nil → 「报表功能未配置」错误      # 配置不足显式报告调用方
reporter: JiyuanReport → 3×QueryContext → BuildReport → Report
```

## 三条 SQL（上游契约：本地从库 newapi 库）

1. **sqlDetails**：logs JOIN channels（name LIKE %nameLike%）按 渠道×model×upstream_model 分组——calls/ok(type=2)/fail(type=5)/ptok/ctok/cache_tokens(JSON_EXTRACT other)/upstream_model(JSON_UNQUOTE，COALESCE 回退 model_name)。**created_at >= 起点（今天 0 点 −(days−1) 天，本地时区）**
2. **sqlPrices**：model_price_snapshots 每模型 MAX(snapshot_at) 的最近一行（input/output/cache 三价）
3. **sqlDaily**：FROM_UNIXTIME(created_at,'%m-%d') 按天聚合（调用量/成功失败/tokens；不含消费列——快照是当前价，按天算会误导）

## BuildReport（纯函数）

- 价格查找：upstream → model → 零价 + MissingPrices（去重排序）
- 消费：`nonCache = max(0, ptok−cachetok)`；`cost = nonCache/1e6×input + cachetok/1e6×cache + ctok/1e6×output`
- 聚合：渠道汇总（按 calls 降序）/ 模型汇总（按计费模型，附三价）/ 渠道×模型明细 / Total

## 测试

- 纯函数测试不碰 DB（TestBuildReportCostAndAggregation：27.6 元手工核算用例、缺价、负缓存钳制）
- SQL 本体不在单测覆盖内（需真库）；数据源连通性用从库实测验证（24 模型有价、4 天窗口数千行）
