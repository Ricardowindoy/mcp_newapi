# registry 功能说明

工具注册层（internal/mcp/registry.go + server.go）：**对外服务的唯一汇总表**。agent 能看到哪些工具、什么参数、什么描述，全部由本模块一张表决定。

## 职责

- `toolDef` 四要素：Name / Tier（档位）/ Options（描述+参数声明，mcp-go ToolOption）/ Handler 工厂（`func(*newapi.Client, *reporter.Store) handler.Handler`，第二参数为报表从库连接，entry 从 config 注入，仅 jiyuan_report 使用）
- `toolRegistry` 汇总表 23 项：read 档 11（status/list_models/list_channels/get_channel/list_tokens/logs/usage_summary/pricing/list_options/success_rate/jiyuan_report）+ ops 档 6（test_channel/test_all_channels/update_channel_balance/set_channel_status/create_token/delete_token）+ admin 档 6（create_channel/update_channel/delete_channel/update_option/autoban_codes/tag_channels）
- `registerTools` 档位过滤：writemode 映射上限（admin→2 / ops→1 / 其他→0），`def.Tier > max` 跳过——**低档不含高档工具（不注册而非注册后拒绝）**，Agent 无法试探
- `NewServer`：装配 `server.NewMCPServer("newapi-mcp", "0.5.0", WithToolCapabilities(false))` 后走 registerTools；报表从库连接由 entry 从 config 注入，**rep 为 nil 时 jiyuan_report 仍注册、调用时报配置错误**
- registry_test.go：TestRegistryIntegrity（表完整性）+ TestTierFiltering（各档注册数量）

## 边界

- 不做参数解析、不做业务逻辑（handler 层的事）
- 新增/调整工具**只改本模块表项 + 对应 handler 实现**，server.go 不动；描述文案是给 Agent 的提示词，要求写清前提（如「需管理员 PAT」「实例可能禁用」）
- server 名字/版本号硬编码在 server.go；Tier 数值序 read=0 < ops=1 < admin=2，与 config 的 writemode 字符串通过 switch 映射，两端新增档位需同步
