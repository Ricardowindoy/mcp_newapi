## 类型与常量

```go
type tier int          // tierRead=0 / tierOps=1 / tierAdmin=2
type toolDef struct {
    Name    string
    Tier    tier
    Options []mcp.ToolOption
    Handler func(*newapi.Client, *reporter.Store) handler.Handler
}
```

## registerTools 档位映射

| writemode | max tier | 注册数 |
|---|---|---|
| "admin" | tierAdmin(2) | 23 |
| "ops" | tierOps(1) | 17 |
| 其他（含 "read"/空/未知） | tierRead(0) | 11 |

未知 writemode 静默按 read 处理（config.Validate 已拦截非法值，这里是双保险）。注册循环用 `def := &toolRegistry[i]` 取址遍历（避免 Go range 变量拷贝语义），最后 `s.AddTool(mcp.NewTool(def.Name, def.Options...), def.Handler(client, rep))`。rep（报表从库连接）由 entry 从 config 注入，nil 时 jiyuan_report 仍注册、调用时报配置不足错误。

## 表项声明规范（每项两件套）

1. `Options`：`mcp.WithDescription` 必填——文案面向 Agent，写清权限前提（需管理员 PAT/无需鉴权）、语义注意（测试失败是有效结果/异步任务/不透出完整 key）；参数用 WithNumber/WithString/WithBoolean，必填 `mcp.Required()`，有默认值配 `DefaultNumber`
2. `Handler`：指向 handler 包对应工厂（StatusHandler…DeleteChannelHandler）

删除类工具（delete_token/delete_channel）、全局生效的 update_option / autoban_codes（变更项）、批量生效的 tag_channels 在表里声明 `confirm` 必填布尔参数，handler 内再校验——表单校验是第一道，handler 校验是兜底。

## 测试（registry_test.go）

- TestRegistryIntegrity：表内 Name 非空唯一、每项有描述、删除类带 confirm 参数等表完整性断言
- TestTierFiltering：三档 writemode 下 registerTools 注册数量 11/17/23

新增表项后两个测试都应扩断言（数量、唯一性自动覆盖新项）。

- server.go 的 `server.NewMCPServer("newapi-mcp", "0.5.0", …)`：版本串硬编码，升版需手动同步（MCP 客户端可见）
